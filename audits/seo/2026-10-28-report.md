# SEO / GEO audit — My Pokédex — 2026-10-28

- **Site:** my-pokedex (https://my-pokedex.com)
- **Mode:** AUDIT (full re-run of every non-deprecated check in `skills/seo/checks.json`; no site code changed this run)
- **Stack:** Next.js 16 Pages Router, static export → Cloudflare Workers static assets
- **Ad status:** ad-free (AdSense abandoned 2026-07-09, Nintendo IP; GA4 removed `7da08ec`) — ad/consent scopes N/A
- **Locales:** EN + FR (`/fr` subtree), 1,202 URLs each
- **Audited target:** live prod https://my-pokedex.com. Prod was serving build `74950c5` (per `/sw.js` VERSION) during the crawl. Repo `master` HEAD at commit time adds only Dependabot lockfile and dependency bumps on top of it (see the sidecar `target.ref`).
- **Pages audited:** **2,404**, i.e. every `<loc>` in the live sitemap, fetched as raw HTML (no JS). A BFS over internal `<a>` links from `/` reached the same 2,404 URLs and nothing else.
- **Method / tooling:** Node `fetch` + linkedom crawler (raw HTML), a pairwise near-duplicate pass over all descriptions (word-set Jaccard ≥0.8), sitemap `xhtml:link` hreflang reciprocity over all 2,404 entries, a schema.org vocabulary check (`schemaorg-current-https.jsonld`: types, properties, inherited domains) on a 67-page stride sample, `dig @1.1.1.1/@8.8.8.8`, `curl` by name with crawler UAs, Lighthouse 13 (mobile + desktop, repeated runs), and a Playwright `PerformanceObserver('layout-shift')` trace.
- **Validator note:** validator.schema.org redirects automated POSTs to a Google CAPTCHA, so I used the official vocabulary file with the same type and property-domain logic.

## Result

**Score-relevant open findings: 6 issue rows (no critical, no serious).** Crawl, index, canonical, hreflang, DNS, robots, PWA, security headers and AI access are all clean across the full 2,404-URL crawl. The open items are metadata length and templating, two schema defects, an anonymous publisher, and lab CLS on a few templates.

## Checks run

### raw-html-content
PASS. All 2,404 pages ship their main content in raw HTML. Min `<main>` text is 167 chars (`/contact`, a one-line contact page); detail pages carry the dex entry, base stats, profile, abilities, both damage tables and the evolution line server-rendered (`/pokemon/pikachu`: "Base stats Hp35 Attack55 …").

### robots-txt-valid
PASS. `/robots.txt` returns 200: `User-agent: *` / `Allow: /` / `Sitemap: https://my-pokedex.com/sitemap.xml`.

### robots-prod-vs-repo
PASS. Prod `/robots.txt` is byte-identical to `public/robots.txt`. Curls with the Bingbot, GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-User, PerplexityBot, Perplexity-User, Google-Extended, CCBot and Applebot UAs all get 200 with the same md5, so there is no CDN-injected managed robots or Content-Signals. A *Googlebot*-UA curl from a non-Google IP gets a Cloudflare challenge (403). That is the portfolio's Googlebot-impersonator rule (`… and not cf.client.bot`); verified Googlebot is exempt.

### sitemap-valid
PASS. `/sitemap.xml` returns 200 `application/xml` with 2,404 `<loc>`s. **All 2,404 return 200** with no redirects, and all are indexable. (`/sitemap-index.xml` is a real 404, which is correct because there is no index file.)

### canonical-present
PASS. 2,404/2,404 pages have exactly one absolute, self-referencing canonical.

### canonical-resolves-200
PASS. Every canonical target returns 200 directly.

### host-canonicalization
PASS. Checked by name: `http://apex` → 301 `https://apex`, `https://www` → 301 `https://apex`, `http://www` → 301 `https://www` → 301 `https://apex`, `https://apex` → 200. All four reach the canonical origin through 301s. The two-hop `http://www` chain is cosmetic.

### public-dns-resolution
PASS. Apex and `www` resolve from 1.1.1.1 and 8.8.8.8 to Cloudflare A (`104.21.67.218`, `172.67.181.102`) and AAAA (`2606:4700:3036::ac43:b566`, `2606:4700:3037::6815:43da`) records.

### indexability-directives
PASS. No `noindex` on any of the 2,404 sitemap pages and no `X-Robots-Tag` on the sampled responses. Only the 404 page carries `noindex`, which is correct.

### soft-404-real-status
PASS. `/this-page-does-not-exist-zz9` and `/pokemon/zzz-nope` both return HTTP **404**.

### lastmod-honest
PASS. **The prior open finding (all 2,404 URLs flat at 2026-07-07) is resolved.** Commit `be1c540` derives per-Pokémon `lastmod` from each entity's content hash (`scripts/generateSitemap.mjs`, `data/lastmod.json` store). Live distribution: 2026-10-17 ×1,924, 2026-07-07 ×354, 2026-10-18 ×126, so dates move only with content.

### title-length
**FINDING #1 (moderate).** All 2,404 titles are unique and none is short (min 54). But 2,364 exceed ~60 chars (61–82; 207 over 70), because the detail template's 52-char suffix ` — Stats, Types, Weaknesses & Evolution | Pokédex` pushes almost every title over. SERPs will truncate the brand.

### title-unique
PASS. 0 duplicate titles across 2,404 pages.

### meta-description-unique
**FINDING #2 (minor).** 0 byte-identical descriptions. But the pairwise near-duplicate pass flags all **342 type-interaction pages (171 EN + 171 FR)**: each pair differs only in the type name inside one fixed sentence. Detail pages are fine. They carry real per-entity data (category, type, generation, base-stat total); the only near-duplicate detail pairs are 16 EN + 16 FR evolution or species pairs that genuinely share type, generation and BST (e.g. Nidorina/Nidorino, Plusle/Minun), which is acceptable.

### meta-description-length
**FINDING #3 (minor).** None short (min 116). 85 above 160 (max 174).

### single-h1
PASS. Exactly one `<h1>` on all 2,404 pages.

### html-lang
PASS. `lang="en"` on 1,202 pages and `lang="fr"` on 1,202.

### viewport-meta
PASS. `initial-scale=1.0, width=device-width` on all pages, with no zoom lock.

### hreflang-valid
PASS. Alternates are declared in the sitemap (`xhtml:link`) for all 2,404 URLs: `en`, `fr`, `x-default`. Every entry includes itself, every alternate is a sitemap URL (all 200), every pair is reciprocal (0 missing return links), and each page's `<html lang>` matches its own hreflang code.

### schema-valid
**FINDING #4 (moderate, count 2).** All JSON-LD parses (0 parse errors across 2,404 pages; types: BreadcrumbList 2,222, WebSite 1, Organization 1). Vocabulary check on a 67-page stride sample:
- (a) `inLanguage` on `BreadcrumbList` is not a valid property for that type. It appears on every FR detail page sampled (26/26). Source: `utils/structuredData.ts:30-36`.
- (b) Home `WebSite.potentialAction` = `SearchAction` with `query-input`, the Sitelinks Searchbox, which Google retired on 21 Nov 2024 and the skill lists as 🚫 do-not-implement. Keep plain `WebSite` and drop `SearchAction`. Source: `utils/structuredData.ts:11-16`.
Observation (not scored): the 171 FR type-interaction pages, `/fr`, `/fr/type-interactions` and the 8 legal pages have no JSON-LD, while their EN counterparts have breadcrumbs. Schema is optional, so this is parity hygiene only.

### schema-matches-content
PASS. Sampled breadcrumbs match the visible `<h1>` (`["Pokédex","Pikachu"]` ↔ h1 "Pikachu", `["Pokédex","Type Interactions","Electric / Water Types"]` ↔ h1 "Electric / Water Types — …"). `Organization.logo` resolves (`/icons/icon-512.png` 200). No ratings or dates are asserted.

### og-image-present
PASS. `og:image` is on all 2,404 pages and never SVG (`/images/og-default.png` PNG, detail pages `/pokemon/full/NNN.webp`). Sampled images return 200.

### open-graph-complete
PASS. `og:title`, `og:description`, `og:image`, `og:url` (equal to the canonical) and `og:type`, plus `twitter:card`, are present on all 2,404 pages.

### favicon-icon-set
PASS. `/favicon.ico` 200, `/icons/favicon-32.png` and `-16.png` linked, `/icons/apple-touch-icon.png` 200, manifest linked. Observation: the home `<head>` repeats `<link rel="manifest">`, `<link rel="apple-touch-icon">` and each CSS chunk twice. That is harmless to installability, but it is duplicated head output.

### manifest-installable
**Candidacy: PWA, yes.** A Pokédex is a reference people re-open, and it already ships a manifest. **Installability passes.** `/site.webmanifest` has `display: standalone` and `start_url: /`, with icons `/icons/icon-192.png` (192×192), `/icons/icon-512.png` (512×512) and `/icons/icon-512-maskable.png` (512×512, maskable), all 200 PNG. Maskable safe zone, re-measured: art reaches **182.5 px** of the 204.8 px radius, so nothing is clipped. **Offline:** `/sw.js` returns 200 (versioned to the build sha).

### core-web-vitals
**FINDING #6 (moderate).** LCP and TBT are good on every sampled template: Lighthouse mobile LCP 0.8–1.4 s, TBT 10–90 ms, perf 94–100. Desktop LCP 0.2–0.3 s. **CLS exceeds the 0.1 "good" threshold on three templates:**
- `/` desktop: Lighthouse CLS 0.685 (perf 77) and 0.085 on a rerun; Playwright trace 0.673 then 0.084. Shift source: `HEADER.Home-module__pageHeader` and `DIV.VirtualGrid-module__windowed` move from x=0/full width to x=115/1120 px about 0.6–1.0 s after load, so the layout snaps to its container width late.
- `/fr/about` desktop: CLS **0.252** on all three runs (paragraphs in `LegalLayout` shift ~34 px up).
- `/about` mobile: CLS **0.150** on two runs (`article.LegalLayout-module__wrap > p`).
- Clean: `/pokemon/pikachu` 0.007–0.015, `/fr/pokemon/pikachu` 0, `/type-interactions` 0, `/privacy`, `/terms`, `/contact` 0.
Field CWV (CrUX) is pending (handover).

### security-headers
PASS. `strict-transport-security: max-age=31536000; includeSubDomains`, `x-content-type-options: nosniff`, `referrer-policy: strict-origin-when-cross-origin`, `x-frame-options: SAMEORIGIN` and `permissions-policy: geolocation=(self), camera=(), microphone=()` are served on `/`, matching the baseline exactly. No CSP, which the skill says to author last, so it is not a finding.

### ai-crawler-access
PASS. `robots.txt` allows all. Every AI retrieval, agent and training UA probe got 200 on `/robots.txt` and `/`, and no blanket CDN training block was observed.

### publisher-identity-visible
PASS. The visible brand is "My Pokédex" with a clear unofficial fan-site and trademark disclaimer (footer + `/about`), and a real contact address. There is no placeholder or joke identity string (`Organization.name` = "My Pokédex").

### eeat-identity
**FINDING #5 (moderate).** Trust content exists: About, Privacy, Terms, Contact, a "last updated" date, a data-provenance statement and an IP disclaimer. But **no person or entity stands behind the site** ("an independent developer"), the only contact is a mailto, and no page cites a data source. The skill calls that the biggest single trust gap. Fixing it is an owner decision: on an IP-adjacent fan site the anonymity may be deliberate. Never fabricate an identity.

### content-spam-guardrails
PASS. 1,025 detail pages × 2 locales, each carrying distinct per-entity data (stats, types, matchups, evolution). 171 type-combination pages carry computed matchups. No outbound links to other portfolio sites (no external links at all), no doorway pages, no scaled thin pages (min main text on a data page is well above the 167-char contact page).

### orphaned-pages
PASS. A BFS from `/` reaches all 2,404 sitemap URLs: 0 orphans.

### click-depth-exceeded
PASS. Max depth 3 (depth 0: 1, depth 1: 1,031, depth 2: 1,201, depth 3: 171), so 0 indexable pages deeper than 3.
