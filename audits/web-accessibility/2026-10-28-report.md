# Web Accessibility Audit — my-pokedex — 2026-10-28

**Standard:** WCAG 2.2 AA · **Mode:** AUDIT (full re-run of every non-deprecated check in `skills/web-accessibility/checks.json`; **no site code changed**, so the findings are reported, not fixed) · **Auditor:** Claude (automated agent, `web-accessibility` skill)
**Verification ceiling:** this records automated and agent-executable results only. Human and screen-reader verification is still pending (see Handover).

## Project profile
- **Stack:** Next.js 16 Pages Router, React 19, static export, Cloudflare Workers static assets. Client-side routing via `next/link`.
- **Site type:** bilingual (EN/FR) Pokédex reference: home grid with search, type filter and sort; 1,025 detail pages per locale; type-interaction chart (single and dual); legal pages.
- **Feature inventory:** one form (site search). Type-filter chips (`aria-pressed`). Type-filter drawer (`aria-expanded`/`aria-controls`). Mobile "Options" bottom sheet. Theme and resolution icon toggles. Native `<details>` A–Z browse index. `aria-live` result count. No audio, video or iframe.
- **Target:** live prod https://my-pokedex.com. During the run prod served build `74950c5`, and repo `master` adds only dependency bumps since then (sidecar `target.ref`).

## Harness (this run)
Playwright 1.64 Chromium plus `@axe-core/playwright`, installed in a scratch dir outside the repo and run against **live prod**:
- axe with tags `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22a, wcag22aa` on **15 routes × 2 viewports** (1280×900 and a true 320×640): `/`, `/?types=fire`, `/pokemon/pikachu`, `/pokemon/charizard`, `/type-interactions`, `/type-interactions/fire`, `/type-interactions/fire-water`, `/fr`, `/fr/pokemon/pikachu`, `/fr/type-interactions/feu`, `/about`, `/privacy`, `/contact`, `/terms`, and a real 404.
- **7 states:** type-filter drawer open, chip "Fire" pressed, search submitted, mobile Options sheet open, A–Z browse disclosure open (mobile), type-interactions chip pressed, and the theme toggled.
- Keyboard walks: 70 Tabs on 6 routes and 40 at 320 px, recording the ring, obscured stops and tabindex. Plus a sheet-specific walk and a skip-link activation check.
- Reflow at 320 px on 15 routes, an 85-URL stride sample, and the **120 longest-named detail pages**. Also 400 % zoom (320×256), reduced motion, and a text-spacing override.
- **Contrast hand measurement of all 1,183 axe-`incomplete` nodes** on 8 routes × 2 viewports. Method: transitions off, then two screenshots of each element box (text visible / all text transparent). The pixels that differ are the glyph pixels, and each one's true background is compared with the text colour (alpha-composited). Results: 1,084 pass, 79 fail, and 20 have no glyph pixels (clipped or hidden).
- `eslint-plugin-jsx-a11y` **recommended** (the skill's template) over all 67 tracked `.tsx` files, in a scratch copy. The repo's `next lint` script no longer exists in Next 16.
- Lighthouse 13.

## Definition of Done — per check

### axe-violations
On the 30 route×viewport runs and 15 reduced-motion runs: **0 violations**. Across the 7 states the only violated rule is `target-size`, in the A–Z browse state, which is recorded once under **target-size** (#6) rather than counted twice. axe `incomplete` (`color-contrast`) items were all hand-measured (text-contrast).

### keyboard-operable
PASS for the top flows, all done by keyboard on desktop:
- (1) search: type "pika", press Enter, results update (live count "1 Pokémon"), then Tab to the card and press Enter to open the detail page.
- (2) type filter: "Filter by type" (`aria-expanded` toggles), Space on the "Fire" chip (`aria-pressed=true`), live count "81 Pokémon".
- (3) detail Prev/Next links.
The mobile Options sheet opens and closes with its toggle button. Escape does nothing (see #3).

### no-keyboard-trap
PASS. No trap: every walk either wraps to the top (`/pokemon/*` after 26 stops, `/type-interactions` after 33) or keeps traversing the long list. The Options sheet does not trap; focus escapes behind it, which is #3.

### visible-focus
**FINDING #3.** Desktop walks: every stop shows a ring. The search `<input>` itself has `outline: none`, but its wrapper draws a 2 px `#2f6fed` `:focus-within` outline, verified. 0 obscured stops in normal page state. Failure: with the mobile Options sheet open, focus moves behind the sheet and is fully obscured (2.4.11).

### focus-order-logical
PASS. No positive `tabindex`. Order: skip link → logo → primary nav → search → controls → main → footer. Hidden controls are removed from the order (`inert` sheet when closed, `display:none` mobile duplicates).

### skip-link
PASS for presence and function: the first Tab stop is "Skip to main content" (`#main`), Enter focuses `<main id="main">`, and the next Tab lands in main. Its legibility fails, though (red on red, recorded as #1 under text-contrast).

### reflow-320
**FINDING #4 (2 defects).** The 15 audited routes and an 85-URL stride sample have no page-level horizontal scroll, except `/type-interactions` and `/fr/type-interactions` (328 px). Detail pages with long names lose content to `overflow: hidden` clipping without any scrollbar. This is only visible through the element-rect sweep of the 120 longest-named detail pages, 82 of which clip.

### zoom-400
At 320×256 CSS px (1280×1024 at 400 %) I found the same two defects as reflow-320. They are counted once there, not again here. No fixed or sticky element covers more than 50 % of the viewport, and the bottom tab bar is 60 px.

### zoom-not-disabled
PASS. Viewport `initial-scale=1.0, width=device-width` (`width=device-width` on the 404), with no `maximum-scale` or `user-scalable=no`.

### reduced-motion
PASS. Under `prefers-reduced-motion: reduce`: 0 infinite or >500 ms animations on all 15 routes, and axe shows 0 violations in that mode.

### text-contrast
**FINDING #1 + #2.** axe `color-contrast` shows 0 violations, and 1,084 of the 1,183 incomplete nodes pass when hand-measured. That includes type chips (e.g. "Bug" median 6.3:1), the large detail `<h1>` and the type-matchup chips. The failures are the skip link (#1, found by the keyboard pass because axe never sees it focused) and the home-grid stat labels (#2, 4.26–4.49:1).

### ui-contrast
PASS. The search wrapper's `:focus-within` ring `#2f6fed` is 4.5:1 against white. The other stops use the UA default focus ring (outline present at every desktop stop). Type chips show state through a ring plus `aria-pressed`, not colour alone. I did not exhaustively hand-measure the non-text contrast of the icon toggles; they read clearly on screenshots.

### form-labels
PASS. The only form control, the search field `#nameInputId`, has a programmatic `<label>` (axe `label` passes). The sort `<select>` is named "Sort Pokémon list".

### headings-landmarks
**FINDING #5.** One `<h1>` per page on all 15 routes, with no skipped levels where `h2`s exist (type pages `122`, legal `122`). Detail pages have no section headings at all. Observation, not scored: detail and home pages have no `banner` or `contentinfo` landmarks, and the footer `<nav "Footer">` sits inside `<main>`. Landmarks are not required by WCAG, but that structure is unusual. The detail Prev/Next `<nav>` has no label, which makes it the third, unnamed navigation landmark.

### accessible-names
PASS. axe `button-name`, `link-name` and `image-alt` are clean. Icon buttons are named ("Filter by type", "Options", "Submit"). Observation (P2, not scored): the theme and resolution toggles are named by their *current state* ("light"/"dark", "low res.") with no `aria-pressed`, so the name changes on activation and does not say what the button does. "Dark theme" plus `aria-pressed` would be clearer (2.4.6/4.1.2 best practice).

### alt-text
PASS. All `<img>` have `alt` (0 missing across 15 routes). Artwork uses "Pikachu official artwork" or "Illustration de Pikachu". Grid sprites keep the `<name>-pic` / "<name> artwork" alt that the pixelation CSS needs, and decorative glyphs use `alt=""`. Judging how apt the alt text is remains human-only.

### target-size
**FINDING #6.** Everything else passes axe `target-size` at 320 and 1280 (chips, nav, bottom tabs 176×60).

### status-announcements
PASS. `role="status"` / `aria-live="polite"` announces the result count on filter and search changes ("1025 Pokémon" → "81 Pokémon" → "1 Pokémon"). The Next.js route announcer (`role=alert`) announces page titles on client navigation.

### descriptive-links
PASS. 0 generic link texts ("click here", "read more", …) and 0 empty links on all routes.

### aria-current
**FINDING #8.** The primary and bottom-tab "Pokédex" and "Type Chart" links carry `aria-current="page"`. The footer nav does not.

### framework-a11y-lint
**FINDING #7.** jsx-a11y recommended reports 10 errors (4 in rendered code, 6 in dead code). The Next config (`next/core-web-vitals`) jsx-a11y subset reports 0 from the repo's own ESLint config. Non-a11y lint (no-explicit-any etc., 39 errors) is out of scope.

### lighthouse-a11y-100
PASS (floor). Lighthouse 13 mobile accessibility = **100** on `/`, `/pokemon/pikachu`, `/type-interactions`, `/fr/pokemon/pikachu` and `/about`. It did not flag #1–#9 (the skip link is never focused during the run, and the browse disclosure is closed), which shows it is a floor and not proof.
