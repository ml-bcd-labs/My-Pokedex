# Web Accessibility Audit — my-pokedex — 2026-10-29

**Standard:** WCAG 2.2 AA · **Mode:** AUDIT (full prod re-run of every non-deprecated check in `skills/web-accessibility/checks.json` after the 2026-10-28 fix wave; **no site code changed**) · **Auditor:** Claude (automated agent, `web-accessibility` skill)
**Verification ceiling:** this records automated and agent-executable results only. Human and screen-reader verification is still pending (see Handover).

## Project profile
- **Stack:** Next.js 16 Pages Router, React 19, static export, Cloudflare Workers static assets. Client-side routing via `next/link`.
- **Site type:** bilingual (EN/FR) Pokédex reference: home grid with search, type filter and sort; 1,025 detail pages per locale; type-interaction chart (single and dual); legal pages.
- **Feature inventory:** one form (site search). Type-filter chips (`aria-pressed`). Type-filter drawer (`aria-expanded`/`aria-controls`). Mobile "Options" bottom sheet, now modal-like (background `inert`, focus cycle, Escape). Theme and resolution icon toggles. Native `<details>` A–Z browse index. `aria-live` result count. No audio, video or iframe.
- **Target:** live prod https://my-pokedex.com. **Build marker verified:** `/sw.js` reports `VERSION = "62cca2b"`, which equals repo `master` HEAD. The fix markers are live: skip link white on `#b91c1c`, detail `<h2>` section headings, footer `aria-current="page"`, and `inert` on the page while the Options sheet is open (details below).

## Definition of Done — per check

### axe-violations
PASS. **0 violations** on all 30 route×viewport runs, all 15 reduced-motion runs and all 7 states, plus the dedicated `target-size` runs with every `<details>` open (the 10-28 `target-size` failure is gone). axe `incomplete` (`color-contrast`) items were all hand-measured (see text-contrast).

### keyboard-operable
PASS for the top flows, all done by keyboard on desktop:
- (1) search: type "pika", press Enter, results update (live count "1 Pokémon"), then Tab to the card and press Enter to open the detail page.
- (2) type filter: "Filter by type" (`aria-expanded` → `true`), the "Fire" chip (`aria-pressed=true`), live count "81 Pokémon".
- (3) detail Prev/Next links.
The mobile Options sheet opens with Enter and closes with Escape or the toggle.

### no-keyboard-trap
PASS. Page walks either wrap to the top (`/pokemon/*` after 23–26 stops, `/type-interactions` after 34) or keep traversing the long list. The Options sheet's focus cycle is a deliberate modal containment, and Escape always exits it, so it is not a trap (2.1.2).

### visible-focus
PASS (**was finding #3**). Every desktop stop shows a ring. The search `<input>` has `outline: none`, but its wrapper draws a 2 px `#2f6fed` `:focus-within` outline (offset 2 px), re-verified. 0 obscured stops on all 7 walks. With the Options sheet open, 0 of 50 stops are obscured, because the page behind is `inert` (2.4.11).

### focus-order-logical
PASS. No positive `tabindex`. Order: skip link → logo → primary nav → search → controls → main → footer. Hidden controls are removed from the order (`inert` sheet when closed, `display:none` mobile duplicates).

### skip-link
PASS. The first Tab stop is "Skip to main content" ("Aller au contenu principal" on `/fr`), with `href="#main"`. Enter focuses `<main id="main">`, and the next Tab lands on the first card inside `main`. It is now legible: white on `#b91c1c` at 6.47:1 (screenshot checked).

### reflow-320
PASS (**was finding #4, count 2**). At 320 px there is no page-level horizontal scroll on the 15 routes, the 86-URL stride sample, or the 240 longest-named detail pages (e.g. `/pokemon/squawkabilly-green-plumage` wraps its `<h1>` over four lines inside 24–296 px). The only element still exceeding the `Details-module__wrap` box is the decorative, `aria-hidden="true"` "#NNN" watermark `<span>`, and clipping it loses no content.

### zoom-400
PASS. At 320×256 CSS px (1280×1024 at 400 %), the 15 routes and 40 sweep URLs (20 longest-named + 20 stride) show no horizontal scroll and no clipped text. No fixed or sticky element covers more than 50 % of the viewport.

### zoom-not-disabled
PASS. Viewport `initial-scale=1.0, width=device-width` on all 2,404 pages, with no `maximum-scale` or `user-scalable=no`.

### reduced-motion
PASS. Under `prefers-reduced-motion: reduce`: 0 infinite or >500 ms animations on all 15 routes, and axe shows 0 violations in that mode.

### text-contrast
**FINDING #1.** axe `color-contrast` gives 0 violations. Hand-measuring the 1,609 incomplete nodes gives 1,540 measured and 69 with no glyph pixels. The skip link (6.47:1) and the card stat labels (7.16–7.97:1) now pass.
- Measurement artifact, dispositioned: 9 nodes on `/fr` (the footer links, the disclaimer and the A–Z `<summary>`) read 2.2–3.5:1. `/fr`'s grid **infinite-scrolls**, so scrolling the footer into view appends cards and moves the footer between the two capture passes (`scrollHeight` 3,434 → 4,834 → 6,234). `elementFromPoint` confirms the footer links are never covered. These elements use the same CSS classes as the EN home, where they hand-measure 4.57–17.88:1, and the analytic composites on `#e9edf4` are link 13.2:1, disclaimer 9.6:1 and summary 4.55:1. So they pass and are not counted.
- **Failure:** the search placeholder (`opacity .55`) is **2.70:1** light and **4.24:1** dark. The placeholder is text conveying what the field accepts, so 1.4.3 applies, and axe never samples `::placeholder`. Note: the A–Z `<summary>` at `rgba(0,0,0,.55)` is 4.55:1, a pass with no margin.

### ui-contrast
**FINDING #2.** The search field and the sort `<select>` are identified only by a `#d7dce6` 1 px border (1.38:1 against the white header, 1.24:1 against its own fill) and a `#f1f3f8` fill (1.11:1). Dark theme: border 1.51:1, fill 1.16:1 on `#121620`. Both fall below the 1.4.11 3:1 threshold, which the portfolio rule enforces for text-input borders (screenshot `inputs-light-1280`). Other components pass: the focus ring `#2f6fed` is 4.5:1 on white, type chips show state through a ring plus `aria-pressed`, and the white 3 px skip-link outline sits on `#b91c1c`.

### form-labels
PASS. The only form control, the search field `#nameInputId`, has a programmatic `<label>` (axe `label` passes). The sort `<select>` is named "Sort Pokémon list".

### headings-landmarks
PASS (**was finding #5**). One `<h1>` per page on all routes, with no skipped levels. Heading sequences: detail `122222`, type pages `122`, legal `122`. Detail sections are real `<h2>`s in the accessibility tree (EN and FR). Landmarks: one `main` and one `footer` (contentinfo) per page. Navs are named "Primary" ×2, "All Pokémon" / "All type matchups" and "Footer" (FR "Principale", "Pied de page"). Observation, not scored: the detail Prev/Next `<nav>` is still unnamed.

### accessible-names
PASS. axe `button-name`, `link-name` and `image-alt` are clean. Icon buttons are named ("Filter by type", "Options", "Submit"). Observation (P2, not scored, unchanged): the theme and resolution toggles are named by their *current state* ("light", "low res.") with no `aria-pressed`. Also unscored: the Options sheet uses `inert` and `aria-expanded` but has no `role="dialog"`/`aria-modal`/name. It works for keyboard and AT because the background is inert, but announcing it as a dialog would be clearer.

### alt-text
PASS. All `<img>` have `alt` (0 missing across 15 routes). Artwork uses "Pikachu official artwork" or "Illustration de Pikachu", and decorative glyphs use `alt=""`. Judging how apt the alt text is remains human-only.

### target-size
PASS (**was finding #6**). The A–Z browse links measure 24.0–36.8 px tall (1,051 links), and axe `target-size` gives 0 violations at 1280 and 320 with the disclosure open. Chips, nav and bottom tabs also pass.

### status-announcements
PASS. `role="status"` / `aria-live="polite"` announces the result count on filter and search changes ("1025 Pokémon" → "81 Pokémon" → "1 Pokémon"). The Next.js route announcer (`role=alert`) announces page titles on client navigation (e.g. "Water Type — Weaknesses & Resistances | Pokédex").

### descriptive-links
PASS. 0 generic link texts and 0 empty links on all routes.

### aria-current
PASS (**was finding #8**). The footer link to the current page carries `aria-current="page"` on `/about`, `/privacy`, `/contact` and `/terms`. The primary and bottom-tab navs carry it on "Pokédex" and "Type Chart". Observation, not scored: the FR footer links point to the EN legal routes (`Footer.tsx` uses un-localised constants, pre-existing since `f1a0ffd`), so a FR legal page has no footer link to itself to mark.

### framework-a11y-lint
PASS (**was finding #7**). jsx-a11y `recommended` over 65 tracked `.tsx` files gives **0 jsx-a11y errors and 0 warnings**, with no `eslint-disable` of any jsx-a11y rule in the repo. The only output is 9 "rule definition not found" messages for `@next/next/no-img-element` / `react-hooks/exhaustive-deps` disable comments. Those plugins are not loaded in the scratch a11y-only config, so this is not an a11y issue. The repo's own `eslint.config.mjs` now layers `jsxA11y.flatConfigs.recommended` on `next/core-web-vitals` (`18775a2`), so a11y lint gates CI.

### lighthouse-a11y-100
PASS (floor). Lighthouse 13 accessibility = **100** on all 40 runs: mobile + desktop × 2 runs on `/`, `/about`, `/fr/about`, `/pokemon/pikachu`, `/fr/pokemon/pikachu`, `/type-interactions`, `/privacy`, `/contact`, `/terms` and `/fr`. It does not flag #1 or #2: Lighthouse never samples `::placeholder`, and it treats input borders as decoration. So it is a floor and not proof.
